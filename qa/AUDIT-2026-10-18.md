# FT2 Human-Centered QA Audit - 2026-10-18 (audit only, nothing was changed)

Method: the real `index.html` was driven in the QA sandbox (phone 390x844, landscape 844x390, tablet 768x1024, desktop 1280x800; 22 screens and pop-ups at each size),
the deployed Apps Script was probed with **read-only** requests (counts only, no content kept), and the Apps Script source was reviewed. Nothing was written to your Sheet and the app was not modified.
"Verified" = actually run/measured. "Code review" = read in source, not exercised live (writes would have changed your real data).

Not evaluated (needs a person or a device): screen readers (VoiceOver / TalkBack), a true Tab-key walk through every screen, real iPhone / Android behaviour, live write-permission tests on the real server, real clipboard / share sheet.

---------------------------------------------------------------------------------------------------------------------------------

## CRITICAL

**S-01 - Private sessions and share links can be read by anyone who types a coach's name** (Security - data layer - every device)
- Expected: private data only goes to its authenticated owner.
- Actual (VERIFIED live, read-only): the sessions feed identifies the asker only by a free-text `?coach=<name>`. Anonymous request: 23 shared sessions, 0 private, 0 share tokens. Same request naming one coach: 24 sessions (+1 private) and **10 share tokens**. Coach names are listed in the anonymous result, and the Apps Script URL is in the public `index.html`.
- Fix: real per-coach credential (a secret key per coach, or Google sign-in) checked by the script; never return private sessions / tokens on a name alone.

**S-02 - Anyone can edit, delete or create sessions as any coach** (Security - data layer)
- Expected: only the owner can change or delete a session.
- Actual (CODE REVIEW; not run live): `upsertSession` / `deleteSessionRow` compare `requestingCoach` - a value the caller supplies in the request body - with the stored `createdBy`. Typing the owner's name passes the check. The script's own comment says so.
- Fix: same credential as S-01, checked on every write.

**S-03 - Stored script injection: a crafted shared session runs code on other coaches' phones** (Security - Saved Session detail, Copy Session toast)
- Expected: text from other coaches is always shown as plain text.
- Actual (VERIFIED in sandbox): a session whose exercise `name` contains HTML executes when any coach opens it (`savedExRowHtml` prints `${e.name}` unescaped) - also on the "Session saved" sheet and when copying (`showToast("Duplicated \"${src.name}\"")` is inserted as HTML). Session name, comment, createdBy, date, focus, age, style, phase label, coach name were all clean on 12 screens. With no Content-Security-Policy, injected code could read the device's stored sessions and call the script as that coach (and S-01/S-02 let anyone post such a session).
- Fix: escape every interpolated value (exercise names, toasts); clean text when it arrives from the Sheet; add a CSP.

## MAJOR

**S-04 - The shared-session list is public** (Security / Privacy - Community)
- Expected: community data visible to signed-in coaches. Actual (VERIFIED): `?sheet=sessions` with no name returns every shared session with coach names, notes and ratings to anyone with the URL. Fix: require the credential from S-01.

**S-05 - Private notes and ratings are shared by default** (Privacy - Saved Session, Community)
- Expected: "how this session went" notes stay with the coach unless they choose otherwise. Actual (code review + UI): new sessions default to Shared; the script sends `comment` and `rating` for shared sessions and the detail page shows another coach's note. Verified live: 1 shared session carries a note. Fix: strip notes / ratings for non-owners on the server; consider defaulting to Private.

**S-06 - Making a session Private does not switch off its share link** (Privacy - Saved Session / Share)
- Expected: Private = nobody else can open it. Actual (code review): `readSharedSession` ignores visibility and `toggleSessionVisibility` leaves `shareToken` in place; no "stop sharing" / new-link option exists. Only deleting the session kills the link. Fix: clear (or regenerate) the token when going Private; add "Stop sharing".

**S-07 - Spreadsheet formula injection** (Security - Apps Script)
- Expected: typed text is stored as text. Actual (code review, known Apps Script behaviour; not run to avoid writing to your Sheet): `setValues` stores a string starting with `=` as a formula, so a session name / note like `=IMPORTDATA(...)` runs inside your Sheet. Fix: prefix such values with an apostrophe or force plain-text cells.

**S-08 - Public write endpoint has no limits or schema checks** (Security - Apps Script)
- Expected: size / count / shape limits. Actual (code review): no length, count or schema limits; anyone can create unlimited rows under invented coach names (they appear in everyone's Community, see S-03); the owner can also rewrite `createdBy` on their own row. Fix: validate and cap fields, rate-limit, ignore client `createdBy`.

**UX-01 - Exercise Detail text looks editable but edits are lost** (Usability - Exercise Detail, U-03/U-04)
- Expected: an edit is either clearly saved or not offered. Actual (VERIFIED): 5 fields are directly typeable with no Edit / Save; after closing and reopening the text is back to the Sheet's. Nothing is sent to the Sheet. Fix: make it read-only, or add a clear edit mode that saves (and says where).

**A-01 - Rows and exercise cards cannot be used with a keyboard** (Accessibility - Home, Sessions, Library)
- Expected: Enter / Space opens an item. Actual (VERIFIED): Home recent rows and My Sessions rows are focusable `role=button` but ignore Enter/Space; exercise cards and names are plain clickable `div`s (not focusable). Fix: real buttons or key handlers; tabindex + role on cards.

**A-02 - Pop-ups are not accessible dialogs** (Accessibility - all sheets / alerts)
- Expected: `role=dialog`, focus moves in, Esc closes, focus returns. Actual (VERIFIED): no `role`/`aria-modal`, focus stays behind the pop-up, Escape does nothing (0 Escape handlers in the app). Fix: add dialog semantics, focus management, Esc.

**A-03 - In phone landscape most of the screen is fixed bars** (Responsive - Setup, Build, Review, Custom steps)
- Expected: a usable scrolling area. Actual (VERIFIED, 844x390): top bar 62 + bottom nav and button 159 leave **169px of 390px**, and the docked Back pill takes 60 more, so about 109px scrolls. (Portrait, tablet, desktop: fine.) Fix: hide / shrink the bottom bar and put the main button inline in landscape.

## NO ISSUES FOUND (actually evaluated)
- **Share-token handling:** 24-char random tokens (2,000 generated, all unique); invalid, wrong-format, 200-char and injection-style tokens all return `not_found` (4 live read-only tests); the shared page gets only plan fields (code review). Deleted-session links: code removes the row so the token no longer resolves (code review, not run live).
- **Input echo:** coach name, session name, comment, createdBy, date, focus, age, style and phase labels were escaped on every screen tested (only the two sinks in S-03 failed); invalid session / exercise IDs show "not found" without echoing the value; no `eval`; no secrets in the file; `target=_blank` links all have `noopener`.
- **Bookmark = favorite:** no heart icon anywhere; one bookmark icon family.
- **Navigation consistency:** Sessions stays lit through Setup, Build, Review, Find Exercises, Custom steps, Saved Session and Templates opened from Sessions; Exercises lit only for the global library; choosing exercises for a session never switches the tab; Back goes to the screen you came from in all 12 flows tested; forward buttons read "Next: ..." / Save.
- **Primary / secondary buttons:** one yellow style and one pop-up border across 102 pop-up buttons (light and dark).
- **Responsive:** no sideways scroll on 22 screens at all four sizes; the last item always clears the bottom bar; no clipped text in fixed-height boxes; no controls overlap (the overlaps the scan flagged were intentional: bookmark on a thumbnail, the docked button over scrolled content, pop-up backdrops); zoom is not locked; `lang` is set; reduced-motion is respected.
- **Tasks that worked well:** U-09 resume draft (Home and Sessions, survives reload, guarded "start new"); U-05 find a saved session (search, sort, filter); U-07 share (one tap, "Session Link Copied" feedback); U-08 print (format, size, preview, "ready"); U-03 find an exercise (search always visible); U-02 custom session (5 taps).
